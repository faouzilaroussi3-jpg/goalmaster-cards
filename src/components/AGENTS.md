## Components rules
- PlayerCard is the shared presentation for collection and pack results; container queries keep names legible at different card sizes, and rarity-token effects respect reduced motion.
- Rare-tier frames (gold, rainbow ALT, diamond + edge gem and small diamonds gravitating over the face on nested rings, navy/white neon-invert Shiny, fire SU) are CSS plus SVG overlays in RareCardFx.tsx keyed off data-rarity/data-version; SU fire is a per-card canvas particle system (CardFire.tsx) paused off-screen; motion is skipped under reduced motion.
- The SU dragon is a single canvas overlay (SuDragon.tsx, re-exported by RareCardFx) that draws a 2D dragon crawling clockwise round the card border: procedural red-metal body segments, a painted side-profile head and claw sprites (src/assets/dragon), and a particle fire breath from the mouth; path geometry (box-blurred border path so corners turn smoothly) lives in src/lib/dragon-path.ts and breath timing in src/lib/dragon-breath.ts (both tested). The overlay padding is mirrored between .su-dragon in styles.css and PAD_X/PAD_Y; it pauses off-screen, boosts CardFire while breathing, and draws one still frame under reduced motion.
- Admin card management lives in admin/CardsAdmin.tsx; edits/deletes go through the admin cards RLS policy, while owner counts (admin_card_stats) and merging cards (admin_replace_card) are admin-checked SECURITY DEFINER functions because user_cards is not readable or writable across users from the client.
- The collection's enlarged card view (CardViewer.tsx) reuses PlayerCard + CardBack on two 3D faces; drag/flip math lives in src/lib/card-viewer.ts with tests, so rotation tuning never touches card rendering.
- Légendaire-or-better reveals play a full-screen canvas build-up/explosion (RareRevealFx.tsx) themed from the card-frame tokens and led by the rarity's own tint; which reveal a rarity gets comes from rarityRevealFx (look, then built-in it plays as, then rank), so any rarity ranked at or above Légendaire always animates; per-variant durations and the tap lock live in src/lib/rare-reveal.ts with tests, so the animation always plays out (Passer still skips) and never touches the server draw.
- Duel UI lives in components/duel (TeamPicker, NewDuelDialog, AcceptDuelDialog) and the duels routes; powers/budget shown there come from src/lib/duel.ts, which mirrors the SQL rules, and AppHeader owns the single realtime subscription on duels.
- LivePulls shows big_pulls (filled by a pack_openings trigger, Légendaire+ only, Secrète Ultime and admin accounts excluded in both the trigger and get_big_pulls) and owns its own realtime subscription on that table.
- Tearing a pack goes straight from the light burst to the face-down reveal stack (no cinematic), so opening stays fast; a quick-open button (PackOpening instant) skips tear and stack straight to the summary; tear thresholds live in src/lib/pack-swipe.ts as pure functions with tests.
- Pack results are revealed from a tap-to-flip stack (CardBack + src/lib/card-reveal.ts timings) in the order open_pack returns (least rare first, slot field); reveal suspense is presentation only.
- Rarity styles draw through .card-style-fx[data-fx]; extra effects are layered by PlayerCard's exported ExtraFx over the main effect, which alone sets fonts/photo treatment.
- CardBack draws a pack's back colour, shape outline (.gm-back[data-shape], same outlines as card shapes) and effects via ExtraFx; back pictures are blended with CSS because backs reshape per pack.
- Custom pack pictures are baked in the browser into a crimped foil pack PNG (src/lib/packify.ts) before upload, so every pack surface (swipe tear, lists, opening, news) stays a plain image.
- 3D (React Three Fiber) lives only in components/avatar and is lazy-loaded by the avatar and ballon-dor routes: Avatar3D is a procedural figurine (printed lathe shirt texture, u = 0 chest / 0.5 back) so kits, hair and shoes stay fully customisable; the ceremony hall uses canvas-sprite name tags and instanced seats/confetti to keep a 40-avatar crowd light.
- Admin player statistics (StatsAdmin) read everything through the admin-checked admin_player_stats function, because user_cards, pack_openings and match rows are not readable across users from the client; ranking rules live in src/lib/admin-stats.ts with tests.
